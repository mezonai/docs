# Channel webhook

A channel webhook posts messages into a single Mezon channel (or thread) under the webhook's configured name and avatar.

<ApiBadge method="POST" path="https://webhook.mezon.ai/webhooks/YOUR_CHANNEL_ID/YOUR_WEBHOOK_TOKEN" />

## Create a channel webhook

You need the **Manage Channel** permission in the clan.

1. Right-click the target channel in the channel sidebar and select **Edit Channel**.

   ![Channel context menu showing Edit Channel](./images/channel-webhook-computer-01.png)

2. Open the **Integrations** tab.

   ![Channel settings Integrations tab](./images/channel-webhook-computer-02.png)

3. Click **Create Webhook** (or **View Webhook** if the channel already has webhooks), then click **New Webhook**.
4. Expand the new webhook and click **Copy Webhook URL**.

   ![Expanded webhook showing Copy Webhook URL](./images/channel-webhook-computer-03.png)

Store the URL in a secret environment variable such as `WEBHOOK_URL`.

## Supported payload formats

`mezon-api` (`webhook_service.go`) inspects top-level JSON keys in **strict priority order** to route incoming requests to one of three built-in parsers:

| Priority | Trigger key | Parser | Best for |
|---|---|---|---|
| 1 | `repository` | **GitHub Webhook** | Connecting GitHub repository webhooks directly without middleware |
| 2 | `type` | **Native Mezon** | Full control over UTF-16 markdown ranges (`mk`), `@mentions`, and `images` |
| 3 | `content` | **Discord-compatible (`COMMON`)** | Drop-in compatibility with Discord-style webhook senders |
| — | *(none of the above)* | Ignored | Returns `200 OK`, but **no message is posted** |

:::tip Key precedence
Because `repository` is checked before `type`, and `type` before `content`, avoid mixing top-level keys from different formats in the same JSON body.
:::

---

### Format 1: Native Mezon (`type` key)

Use any non-empty top-level `type` key (for example `"hook"`) and place your payload inside `message`:

```json
{
  "type": "hook",
  "message": {
    "t": "Build passed: https://example.com/builds/42 @Hoa",
    "mk": [
      { "type": "b", "s": 0, "e": 12 },
      { "type": "lk", "s": 14, "e": 43 }
    ],
    "mentions": [
      { "user_id": "USER_ID", "s": 44, "e": 48 }
    ],
    "images": [
      {
        "url": "https://example.com/chart.png",
        "fn": "chart.png",
        "ft": "image/png",
        "w": 640,
        "h": 360,
        "sz": 42180
      }
    ],
    "username": "ci-bot"
  }
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `type` | string | Yes | Routing key (any value such as `"hook"`). |
| `message.t` | string | Yes | Plain message text. |
| `message.mk` | array | No | Formatting spans `{ "type", "s", "e" }` using UTF-16 code-unit offsets (`e` exclusive). Common types: `"b"` (bold), `"lk"` (link), `"t"` (code block). |
| `message.mentions` | array | No | Mention targets `{ "user_id" or "username", "s", "e" }`. Only members who have access to the channel are notified; others stay plain text. `@here` is not supported. |
| `message.images` | array | No | Image attachments `{ "url", "fn", "ft", "w", "h", "sz" }`. Every `url` must be a full `http://` or `https://` URL or the request fails with `400 Invalid attachment URL`. |
| `message.username` | string | No | Optional metadata string passed to the message dispatcher (Mezon displays the webhook's configured profile name and avatar). |

---

### Format 2: GitHub Webhook (`repository` key)

Paste your Mezon channel webhook URL directly into a GitHub repository under **Settings → Webhooks → Add webhook**, with **Content type** set to `application/json`.

`mezon-api` (`github_handler.go`) automatically formats these GitHub events with clickable markdown links:

- **Push events** (`head_commit`, `commits`, `pusher`, `ref`): displays the sender, repository + branch name, commit count, and up to **5 commits** with commit messages, links, and committer names.
- **Pull request opened** (`action: "opened"`, `pull_request`): displays the sender, repository, `head -> base` branch pair, and PR link.
- **Pull request merged** (`action: "closed"`, `pull_request.merged: true`): displays the sender, repository, `head -> base` branch pair, and merged PR link.

Other GitHub event payloads (such as `ping` or `issues`) return `200 OK` without posting a message.

---

### Format 3: Discord-compatible (`content` key)

Any tool that already sends Discord-style webhook payloads works out of the box when the JSON body contains a top-level `content` key:

```json
{
  "content": "Deployment finished: https://status.example.com\n```bash\nversion=v2.4.0\n```",
  "username": "Release Bot",
  "avatar_url": "https://example.com/avatar.png"
}
```

`mezon-api` (`common/event.go`) automatically detects and converts:

- **`http://` and `https://` URLs** → clickable `lk` markdown ranges (UTF-16 offsets).
- **Fenced triple-backtick code blocks** (```` ```...``` ````) → `t` code-block markdown ranges (UTF-16 offsets).

:::note Discord `embeds` not yet parsed
Only `content`, `username`, and `avatar_url` are modeled in the `COMMON` handler. Discord `embeds` arrays are currently ignored; use the Native Mezon format if you need images or structured formatting.
:::

```bash
curl -X POST "$WEBHOOK_URL" \
  -H "Content-Type: application/json" \
  -d '{"type":"hook","message":{"t":"Build passed: https://example.com/builds/42 @Hoa","mk":[{"type":"b","s":0,"e":12},{"type":"lk","s":14,"e":43}],"mentions":[{"user_id":"USER_ID","s":44,"e":48}]}}'

# Discord-compatible format
curl -X POST "$WEBHOOK_URL" \
  -H "Content-Type: application/json" \
  -d '{"content":"Build passed: https://example.com/builds/42"}'
```

## Limits and error responses

Mezon validates JSON syntax, image URLs, and token ownership synchronously, then enqueues delivery to the channel worker (`webhook_service.go`). Downstream delivery failures (such as a deleted channel) occur asynchronously after `200 OK`.

| Limit | Value | Behavior when exceeded |
|---|---|---|
| HTTP request body | **4 MiB** (`MaxRequestBodySize`) | Rejected by HTTP server before handler executes |
| Serialized Native Mezon message JSON (`t` + `mk`) | **4,000 bytes** | Replaced with `"The original message was too long"` and mentions are cleared (note: multi-byte UTF-8 characters such as Vietnamese accents take 2–3 bytes each) |
| Hashtags (`hg`) | Not supported | Channel hashtags in `t` remain plain text |

| HTTP status | Response body | Cause |
|---|---|---|
| `200` | *(empty)* | Request accepted (or silently ignored if none of `repository`, `type`, or `content` is present). |
| `400` | `Invalid JSON` | Request body is not valid JSON. |
| `400` | `Invalid token` | Token is invalid, disabled, or belongs to a different channel ID. |
| `400` | `Invalid attachment URL` | An entry in `message.images[].url` is not a full URL with scheme and host. |
