# Stream channels

A stream channel shows live video to the members of a clan. A bot can publish video into a stream channel: it gets a short-lived grant from Mezon, then sends its video to the Mezon streaming server over WHIP ([RFC 9725](https://www.rfc-editor.org/rfc/rfc9725)). Members watch in the Mezon apps.

The SDKs give you the grant. They contain no video code: you publish with a WebRTC library of your choice.

## How it works

1. The bot asks Mezon for a publish grant for the channel. It gets a token, a WHIP URL and an expiry time.
2. The bot sends its WebRTC offer to the WHIP URL, with the token.
3. The streaming server answers. The bot connects and sends H.264 video and Opus audio.
4. Mezon tells the clan that the channel is live.
5. Members watch the stream in the Mezon apps, about 6 seconds behind the live picture or more.
6. The bot ends the stream by deleting its WHIP session.

## Before you start

- A stream channel in a clan: see [Stream channel](../../user/clan/create-your-own-clan/manage-clan/clan-structure/channels/stream-channel.mdx).
- The bot must be a member of the clan.
- A WebRTC library that can create an SDP offer with H.264 and Opus and send media.

## Get a publish grant

```ts
const grant = await client.getStreamPlayback({ channel_id: "CHANNEL_ID", publish: true });
if (!grant?.token || !grant.whip_url) throw new Error("No publish grant");
```

In the [.NET SDK](../mezon-sdk/dotnet-sdk.md#stream-channels), call `GetStreamPlaybackAsync(new GetStreamPlaybackParams(channelId, publish: true))`.

| Field | Meaning |
|---|---|
| `token` | The bearer token for the WHIP request. Never log it. |
| `whip_url` | Where to send the WHIP request. |
| `expires_at` | When the token expires, in Unix seconds (a string in `mezon-sdk`). |

The token is valid for 10 minutes. The streaming server checks it only when a session starts, so a running stream continues after it expires. Get a new grant every time you start or restart publishing.

The grant request fails with code 400 if the channel is not a stream channel, and 403 if the bot is not in the channel's clan. In `mezon-sdk` the failure is an object such as `{ code: 0, error: { code: 403, message: "Permission denied." } }`, not an `Error`.

## Publish with WHIP

Send the SDP offer from your WebRTC library to `whip_url`:

```ts
async function startPublishing(channelId: string): Promise<string> {
  const grant = await client.getStreamPlayback({ channel_id: channelId, publish: true });
  if (!grant?.token || !grant.whip_url) throw new Error("No publish grant");

  const offer = await createOffer(); // from your WebRTC library
  const response = await fetch(grant.whip_url, {
    method: "POST",
    headers: {
      "Content-Type": "application/sdp",
      Authorization: `Bearer ${grant.token}`,
    },
    body: offer,
  });
  if (response.status !== 201) {
    throw new Error(`WHIP failed: ${response.status} ${await response.text()}`);
  }

  await applyAnswer(await response.text()); // give the SDP answer to your WebRTC library
  const location = response.headers.get("Location");
  if (!location) throw new Error("WHIP answer has no Location header");
  return new URL(location, grant.whip_url).toString();
}

async function stopPublishing(resourceUrl: string) {
  await fetch(resourceUrl, { method: "DELETE" });
}
```

`createOffer` and `applyAnswer` stand for your WebRTC library's calls. The `Location` header is your session's URL: send `DELETE` to it when you stop. Keep it secret, like the token.

### What the offer must contain

- Audio: Opus at 48 kHz.
- Video: H.264 with `packetization-mode=1`. Use Constrained Baseline (`profile-level-id=42e01f`), so every viewer can decode it.
- At most 4 media sections. The server uses the first usable audio and the first usable video section.
- ICE credentials and a SHA-256 DTLS fingerprint, with `a=setup:actpass` or `a=setup:active`. The server is ICE-lite and always the DTLS server. It does not use trickle ICE, and it supports IPv4 only.

### What the media must look like

- Send the SPS and PPS in band before each keyframe, and encode without B-frames.
- Answer keyframe requests (PLI). If your encoder cannot, send a keyframe every 2 seconds.
- Retransmit lost video packets (NACK) on the original stream: the server does not use RTX.
- Keep sending. A session ends when nothing arrives from the bot for about 15 seconds.

### Answers from the WHIP URL

| Status | Meaning | What to do |
|---|---|---|
| `201` | Session created. The body is the SDP answer. | Connect and send media. |
| `400` | The request or the offer is not valid. | Fix it; do not retry it unchanged. |
| `401` | The token is missing, wrong or expired. | Get a new grant, then retry. |
| `403` | The token is for another channel or role. | Do not retry. |
| `406` | The offer has no codec the server accepts. | Offer H.264 and Opus. |
| `409` | Another user is publishing in this channel. | Tell the user; only one publisher per channel. |
| `413` | The request is too large. | Send a smaller offer. |
| `503` | The server is full, busy or restarting. | Retry later, not before the `Retry-After` header says. |

A new WHIP request from the same bot to the same channel replaces its running session, so a bot that reconnects does not get `409`.

## Know when the channel is live

```ts
client.onStreamingJoinedEvent((event) => {
  if (event.is_publisher) {
    console.log("Live in channel", event.streaming_channel_id, "by", event.user_id);
  }
});
client.onStreamingLeavedEvent((event) => {
  console.log("Left", event.streaming_channel_id, event.streaming_user_id);
});
```

`onStreamingJoinedEvent` with `is_publisher: true` means someone went live. When the stream ends, `onStreamingLeavedEvent` arrives for the publisher.

## Limits

- One publisher per channel at a time.
- Up to 3 simulcast layers and 4 media sections per offer.
- Viewers in the Mezon apps watch over HLS, so they see the stream several seconds late.
