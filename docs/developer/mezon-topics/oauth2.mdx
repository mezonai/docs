# OAuth2

Mezon is an OAuth2 and OpenID Connect provider. Your website can send people to Mezon to sign in, then receive their Mezon user id, username, display name and avatar. This page explains the authorization code flow.

## Set up your app

1. Open the [Mezon developer portal](https://mezon.ai/developers/applications) and open your app (or [create one](../quick-start/creating-mezon-app.md)).
2. Open the **OAuth2** tab.
3. Under **Redirects**, click **Add Redirect** and type your callback URL, for example `https://your-app.example.com/callback`. It must start with `http://` or `https://`.
4. Under **OAuth2 URL Generator**, in **Scopes**, check the scopes your website asks for, then save your changes.
5. Under **Client information**, copy the **Client ID**.
6. Click **Reset secret** to create a client secret, and store it on your server. You need at least one redirect URI first.

The client secret must stay on your server. The flow on this page needs a server.

## Endpoints

These URLs come from the public discovery document at `https://oauth2.mezon.ai/.well-known/openid-configuration` (read on 2026-11-19).

| Endpoint | URL |
|---|---|
| Authorization | `https://oauth2.mezon.ai/oauth2/auth` |
| Token | `https://oauth2.mezon.ai/oauth2/token` |
| User info | `https://oauth2.mezon.ai/userinfo` |
| Revocation | `https://oauth2.mezon.ai/oauth2/revoke` |
| Logout | `https://oauth2.mezon.ai/oauth2/sessions/logout` |
| Signing keys | `https://oauth2.mezon.ai/.well-known/jwks.json` |

## Scopes

| Scope | Gives you |
|---|---|
| `openid` | An ID token with the user's claims (see [User claims](#user-claims)). |
| `offline` | A refresh token, to get new access tokens without asking the user again. |

A new app may request `openid` and `offline`. Ask only for the scopes checked in your app's **Scopes** list.

## Authorization code flow

### 1. Send the user to Mezon

Redirect the user's browser to the authorization URL:

```text
https://oauth2.mezon.ai/oauth2/auth?client_id=YOUR_CLIENT_ID&redirect_uri=https%3A%2F%2Fyour-app.example.com%2Fcallback&response_type=code&scope=openid%20offline&state=RANDOM_STATE
```

| Parameter | Value |
|---|---|
| `client_id` | Your **Client ID**. |
| `redirect_uri` | One of your redirect URIs, URL-encoded. It must match exactly. |
| `response_type` | `code` |
| `scope` | Scopes separated by spaces (`%20`). |
| `state` | A random value you create for this sign-in and keep in the user's session. |

`state` protects against cross-site request forgery: when the user comes back, compare it with the value you kept, and stop if they differ. Use a long random value, for example 32 characters.

### 2. Receive the code

The user signs in to Mezon. Mezon then sends the browser back to your redirect URI:

```text
https://your-app.example.com/callback?code=AUTHORIZATION_CODE&scope=openid+offline&state=RANDOM_STATE
```

Check `state`, then exchange `code` for tokens.

### 3. Exchange the code for tokens

Send a `POST` to the token URL with the body encoded as `application/x-www-form-urlencoded`. The token URL does not accept JSON.

```python
import requests

TOKEN_URL = "https://oauth2.mezon.ai/oauth2/token"
CLIENT_ID = "YOUR_CLIENT_ID"
CLIENT_SECRET = "YOUR_CLIENT_SECRET"
REDIRECT_URI = "https://your-app.example.com/callback"


def exchange_code(code):
    data = {
        "grant_type": "authorization_code",
        "code": code,
        "redirect_uri": REDIRECT_URI,
        "client_id": CLIENT_ID,
        "client_secret": CLIENT_SECRET,
    }
    r = requests.post(TOKEN_URL, data=data)
    r.raise_for_status()
    return r.json()
```

Send the client id and secret in the form body, as above. Mezon sets up apps from the developer portal for this method (`client_secret_post`).

The response:

```json
{
  "access_token": "ACCESS_TOKEN",
  "expires_in": 3600,
  "id_token": "ID_TOKEN",
  "refresh_token": "REFRESH_TOKEN",
  "scope": "openid offline",
  "token_type": "bearer"
}
```

`id_token` comes only with the `openid` scope, and `refresh_token` only with `offline`. `expires_in` is the access token's lifetime in seconds.

### 4. Read the user

Call the user info URL with the access token:

```bash
curl -H "Authorization: Bearer ACCESS_TOKEN" https://oauth2.mezon.ai/userinfo
```

## User claims

With the `openid` scope, the ID token and the user info response carry these claims, when the user has a value for them:

| Claim | Meaning |
|---|---|
| `user_id` | The user's Mezon user id, the same id that bots, webhooks and channel apps see. Store it as a string: it has up to 19 digits. Use this id to identify the user. |
| `username` | The user's username. |
| `display_name` | The user's display name. |
| `avatar` | The URL of the user's avatar. |
| `mezon_id` | An account identifier from Mezon's sign-in service, as an opaque string. It is not the user id. |
| `email` | The user's email address. |

The ID token is a JWT signed with RS256. Check it with the keys from the signing keys URL.

## Refresh and revoke tokens

Get a new access token with the refresh token:

```bash
curl -X POST https://oauth2.mezon.ai/oauth2/token \
  -d grant_type=refresh_token \
  -d refresh_token=REFRESH_TOKEN \
  -d client_id=YOUR_CLIENT_ID \
  -d client_secret=YOUR_CLIENT_SECRET
```

Revoke a token when the user signs out of your website:

```bash
curl -X POST https://oauth2.mezon.ai/oauth2/revoke \
  -d token=REFRESH_TOKEN \
  -d client_id=YOUR_CLIENT_ID \
  -d client_secret=YOUR_CLIENT_SECRET
```
